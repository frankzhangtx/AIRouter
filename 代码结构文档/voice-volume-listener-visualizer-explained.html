Voice Volume Structure

音量监听与音量柱影响链路

这份文档说明项目中录音音量如何从麦克风采样进入监听回调，如何被平滑成 UI 状态， 以及最终如何影响底部可视化音量柱的高度、透明度和波形节奏。

主入口：BottomVoiceRecordController 绑定 PicVoiceRecordPanel
核心文件：app/src/main/java/com/example/cctest/voice/PicVoiceRecordPanel.java
同源实现：app/src/main/java/com/example/cctest/voice/VoiceRecordPanel.kt
采样间隔：60ms，音量范围：0..100

阅读抓手

先看结论，再看下方代码切片和结构图。

当前业务实际使用的是 Pic 面板

BottomInputPanelView 创建 BottomVoiceRecordController， 控制器内部创建并持有 PicVoiceRecordPanel。MainActivity 的 FAB 也直接绑定了 PicVoiceRecordPanel。

监听不是系统音量广播，而是麦克风振幅轮询

PicVoiceAmplitudeRecorder 启动 MediaRecorder 后， 用主线程 Handler 每 60ms 读取一次 getMaxAmplitude()，再转成 0..100 的逻辑音量。

音量柱不直接使用原始采样值

回调只写入 targetVolume。动画帧里通过 displayedVolume += (targetVolume - displayedVolume) * 0.54 平滑追赶目标值，避免柱子随着采样跳变而抖动。

柱高由音量、波形和中心权重共同决定

每根柱子都有按中心衰减的 envelope 和按索引错相的 sin 波。音量越大，柱高越接近最大高度，透明度也更高。

关键参数

参数来自源码常量和 dimens.xml。

MAX_RAW_AMPLITUDE = 32767：按 Android 录音振幅上限做归一化。
SAMPLE_INTERVAL_MS = 60L：音量采样频率约 16.7 次/秒。
WAVE_DURATION_MS = 1100L：可视化波形一轮循环时间。
VOLUME_EASING = 0.54f：显示音量每帧追赶目标音量的比例。
VISUALIZER_VOLUME_AMPLITUDE_MULTIPLIER = 2f：让中低音量也能明显驱动柱高。
MIN_BAR_COUNT = 24：可视化区域至少绘制 24 根柱子。

}

主线程 Handler 临时文件只为 MediaRecorder 输出 异常采样降级为静音

归一化模型

把硬件振幅转换为 UI 音量。

输入：MediaRecorder.getMaxAmplitude() 返回的原始振幅。

裁剪：min(amplitude, 32767)，避免超过预期范围。

曲线：sqrt(raw / 32767f)，用平方根抬高中低振幅的视觉反馈。

输出：(normalized * 100).toInt()，再限制到 0..100。

平方根曲线意味着同样的原始振幅变化，在低音量区会被视觉上放大，用户轻声说话时也能看到音量柱起伏。

代码切片：平滑与绘制

音量柱高度不是单一音量值，而是音量、波形、中心权重的组合。

// updateVolume()：采样回调只更新目标值，实际显示值由动画帧平滑追赶。
void updateVolume(int volume) {
    targetVolume = coerceIn(volume, MIN_VOLUME, MAX_VOLUME);
}

// startAnimating()：每帧推进 wavePhase，并把 displayedVolume 推向 targetVolume。
wavePhase = (Float) animator.getAnimatedValue();
displayedVolume += (targetVolume - displayedVolume) * VOLUME_EASING;
fingerX += (targetFingerX - fingerX) * FINGER_EASING;
fingerY += (targetFingerY - fingerY) * FINGER_EASING;
invalidate();

// drawVisualizer()：逐根计算柱高、透明度，然后绘制圆角矩形。
float volumeRatio = coerceIn(displayedVolume / MAX_VOLUME, 0f, 1f);
float baselineY = panelRect.centerY();

for (int index = 0; index < barCount; index++) {
    float distanceFromCenter = centerIndex == 0f ? 0f : Math.abs(index - centerIndex) / centerIndex;
    float envelope = coerceIn(1f - distanceFromCenter * 0.72f, 0.24f, 1f);
    float wave = (float) ((Math.sin((wavePhase * FULL_CIRCLE) + index * BAR_PHASE_STEP) + 1f) / 2f);
    float amplifiedVolumeRatio = coerceIn(volumeRatio * VISUALIZER_VOLUME_AMPLITUDE_MULTIPLIER, 0f, 1f);
    float activeHeight = visualizerMinBarHeight
        + (visualizerMaxBarHeight - visualizerMinBarHeight)
        * (0.12f + amplifiedVolumeRatio * (0.28f + 0.72f * wave) * envelope);
    int alpha = coerceIn(
        (int) (150 + 105 * envelope * (0.35f + volumeRatio * 0.65f)),
        140,
        255
    );
    barPaint.setColor(withAlpha(ContextCompat.getColor(getContext(), R.color.white), alpha));
    barRect.set(x, top, x + visualizerBarWidth, bottom);
    canvas.drawRoundRect(barRect, visualizerBarRadius, visualizerBarRadius, barPaint);
}

音量如何影响柱子

按一根柱子的计算顺序拆解。

displayedVolume / 100 得到 volumeRatio，代表当前可视音量占比。
volumeRatio * 2 后再裁剪到 0..1，让中等音量也可以接近满幅视觉效果。
envelope 根据当前柱子离中心的距离计算，中心柱最高，边缘柱最低但不低于 0.24。
wave 用 sin(wavePhase * 2π + index * 0.42) 生成，不同索引错开相位。
柱高公式里固定保留 0.12 的基础起伏，所以静音时也能看到低幅度呼吸波。
透明度随 volumeRatio 和 envelope 增加，声音越大、越靠中心越亮。

两套面板差异

同一监听算法，不同视觉容器。

PicVoiceRecordPanel.java

当前输入栏和 FAB 使用的实现。音量柱绘制在一个 44dp 高的胶囊面板内， 面板位置可通过 setRecordPanelAnchorView() 锚定到底部输入栏附近。

VoiceRecordPanel.kt

Kotlin 版大面积录音面板，监听、归一化、平滑和音量柱算法与 Pic 版一致。 额外使用 recordTopCenterY() 让底部录音区域高度随 displayedVolume 上升。

如果排查“底部输入栏语音柱不动”，优先看 PicVoiceRecordPanel.java： 是否成功拿到录音权限、recorder.start() 是否返回 true、sampleRunnable 是否持续回调、targetVolume 是否被更新。

释放路径

停止录音时要同时停采样、停动画、释放硬件资源。

// finishRecording()：根据手指是否在录音区域内决定完成或取消。
boolean wasRecording = recording;
releaseRecording();
removeFromParent();

if (wasRecording && callback != null) {
    if (cancelled) {
        callback.onCancel();
    } else {
        callback.onFinish();
    }
}

// releaseRecording()：停止 recorder 和 Canvas 动画，并重置 UI 状态。
if (recording) {
    recorder.stop();
}
recording = false;
canvasView.stopAnimating();
canvasView.reset();

// PicVoiceAmplitudeRecorder.stop()：移除轮询，停止并释放 MediaRecorder。
handler.removeCallbacks(sampleRunnable);
try {
    if (recorder != null) {
        recorder.stop();
    }
} catch (RuntimeException ignored) {
    // 录音过短时 stop 可能失败，这里吞掉异常并继续释放。
}
releaseRecorder();

释放路径会把 onVolumeChanged 置空、删除临时文件，并把 targetVolume 和 displayedVolume 重置为 0，下一次长按会重新从静音状态开始。
