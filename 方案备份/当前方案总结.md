# 当前自动编程方案总结

## 1. 方案目标

当前实现是 OpenCode coding orchestration V3。用户始终停留在一个
`scheduled-planner` 会话中；模型负责规划、受限编码和只读评审，确定性
Shell 脚本负责状态、证据、Git 分支、提交与本地集成。

核心约束如下：

- 默认不复制整个工程，也不创建额外 Gradle 构建目录。
- 计划、合同、代码、测试和其他授权改动最终只形成一个正常路径提交。
- Coder 和 Reviewer 均不能提交、合并、rebase、push 或自行创建 worktree。
- 自动执行停在人工验收，未经新鲜的选项选择不得集成。
- 原分支发生漂移时只阻断，不自动解决冲突。
- 任何正常路径都不执行 `git push`。

## 2. 用户交互流程

入口为：

```bash
opencode --agent scheduled-planner .
```

会话内通过 `/change` 提交一个自然语言需求。正常流程包含三个 OpenCode
单选控件，不要求用户发送审批文本：

| 阶段 | 控件 | 有效批准选项 |
| --- | --- | --- |
| 方案确认 | `方案确认` | `批准方案，生成计划和任务合同。` |
| 合同复核 | `合同复核` | `合同已复核，批准自动执行到人工验收阶段。` |
| 成果验收 | `成果验收` | `验收通过，提交到原分支。` |

只有对应控件中刚刚选择的选项才有效。聊天中直接发送同名文字、沉默、关闭
控件或选择调整项都不会批准下一阶段。

流程顺序：

1. Planner 运行 source preflight，检查代码和测试，给出单一、有边界的方案。
2. 方案选项批准后，生成 `docs/plans/<TASK-ID>.md` 和
   `automation/tasks/<TASK-ID>.json`。
3. 合同校验通过后封存两份文件的哈希，但不单独提交它们。
4. 人工复核完整合同卡；批准后才启动自动执行。
5. 编排器取得仓库租约，创建任务分支，并运行 Coder、质量门和独立 Reviewer。
6. Reviewer 通过后停在 `AWAITING_HUMAN`，集中展示 SHA 绑定的验收卡。
7. 人工验收通过后创建并验证唯一组合提交，再快进原分支。
8. 原分支安全到达候选提交后删除任务本地分支；不 push。

恢复入口：

- `/acceptance <TASK-ID>`：重新展示当前封存成果验收卡。
- `/resume-review <TASK-ID>`：仅恢复已验证的 Reviewer 中断，不重跑 Coder。
- `/abort-task <TASK-ID>`：经单独确认后封存允许范围内的修改并恢复原分支。

## 3. 工作区与提交策略

`automation/config.json` 当前使用：

```text
workspaceStrategy = inPlaceExclusive
originalBranchDriftPolicy = block
autoCleanupWorktrees = true
pushAfterAcceptance = false
```

合同批准后，脚本从未改变的原始 HEAD 创建任务分支，并让现有工程目录切换到
该分支。计划和合同保持未提交且受哈希保护，直到代码、测试和其他授权修改
一起进入最终组合提交。因此默认路径没有工程复制，也没有独立 planning commit。

只有显式改为 `isolatedWorktree` 时才创建一个任务 worktree；最终验证仍在该
任务根目录完成，不再创建第二个集成候选 worktree。

## 4. 角色与权限

### scheduled-planner

- 唯一允许与用户澄清、显示三个选择控件的角色。
- 只能编辑 `docs/plans/**` 和 `automation/tasks/**`。
- 不能编辑产品代码、自动化核心、OpenCode 配置或受保护构建文件。
- 只能调用白名单事务脚本，不能直接执行 Git 变更命令。

### scheduled-coder

- 只处理合同允许的实现和测试路径。
- 强制使用 TDD、RED 证据、范围门和质量门。
- 最多执行配置允许的一次系统化修复循环。
- 不能修改自动化、Agent、Skill、合同或受保护路径。

### scheduled-reviewer

- 对封存 diff 做独立只读复核。
- 验证合同、范围、测试证据和风险。
- 只能通过 `submit-review.sh` 提交结构化结论。
- 不能编辑任何文件或执行 Git 变更。

### scheduled-quality-orchestrator Skill

- 定义三个人工关口、Reviewer 中断恢复和显式中止边界。
- 要求每次批准都来自新鲜的 OpenCode `question` 选项。
- 禁止模型自行模拟 Git、状态迁移、证据或集成操作。

## 5. 状态机

正常状态链：

```text
CONTRACT_REVIEW
  → APPROVED_CONTRACT
  → PREPARING
  → PENDING
  → CODING
  → READY_FOR_REVIEW
  → REVIEWING
  → AWAITING_HUMAN
  → INTEGRATING
  → COMPLETED
```

硬失败或等待人工处理状态包括：

```text
BLOCKED
TEST_FAILED
NEEDS_HUMAN
INTEGRATION_BLOCKED
CHANGES_REQUESTED
```

显式归档终态为 `ABORTED`。所有迁移由 `lib.sh` 中的允许矩阵校验并记录到
追加式审计日志，角色不能跳过状态。

## 6. 运行时数据

状态、证据、租约和工作区元数据不进入产品 diff，而是写入 Git common dir：

```text
<git-common-dir>/automation-runtime/
├── state/
├── evidence/
├── locks/
└── workspaces/
```

备份时共有三个已完成任务：

- `TASK-FIELD-SEMICOLON-001`：`COMPLETED`
- `TASK-PHONE-DETAIL-LOOKUP-001`：`COMPLETED`
- `TASK-POSITION-DETAIL-OPEN-001`：`COMPLETED`

`locks/` 为空，Git 只报告当前主工作目录，没有遗留任务 worktree。

## 7. 外部依赖

`opencode.json` 当前固定声明：

```json
{
  "plugin": [
    "opencode-scheduler@1.3.0",
    "superpowers@git+https://github.com/obra/superpowers.git#v6.2.0"
  ]
}
```

当前 V3 的正常入口不是定时任务；`automation/scheduler/` 仅保留兼容诊断
提示词，Planner 也明确拒绝 scheduler 工具。`opencode-scheduler@1.3.0`
仍作为已配置依赖保留。

Superpowers 提供当前流程要求的以下 Skill：

- `brainstorming`
- `writing-plans`
- `test-driven-development`
- `systematic-debugging`
- `verification-before-completion`

仓库本身提供：

- `scheduled-quality-orchestrator`
- `scheduled-quality-coder`
- `scheduled-quality-reviewer`

外部包的精确本机副本已放在 `external-dependencies/`，版本引用也保存在
`opencode.json` 和 `automation/config.json` 中。
