# 安全恢复说明

本说明用于插件化改造失败后恢复仓库内的 V3 自动化资源。恢复是覆盖操作，
执行前应先停止 OpenCode 会话并检查当前差异。不要在存在运行中任务时恢复。

## 1. 先验证备份

```bash
./方案备份/verify-backup.sh
```

任一摘要或文件数不匹配时停止，不要使用该快照覆盖工程。

## 2. 确认没有运行中的任务

检查：

```bash
git worktree list
find "$(git rev-parse --git-common-dir)/automation-runtime/locks" \
  -mindepth 1 -maxdepth 2 -print
```

备份时的基线是 `feature-opencode-scheduler`、HEAD
`829693652e3737ad94c7cc75214b09fb2b58715b`，且租约目录为空。恢复时如果
存在任务租约、任务分支处于执行中，或当前目录位于任务 worktree，应先按
当时方案的 `/abort-task` 或专门恢复流程处理，不能直接覆盖。

## 3. 记录插件化改造差异

```bash
git status --short
git diff -- .opencode automation scripts/automation docs/plans \
  taskdescriptions opencode.json AGENTS.md .gitignore
```

先保存这份输出。备份只知道“改造前有哪些文件”，并不知道插件化过程后来
新增了哪些文件；新增文件必须依据这份差异清单逐个处理。不要用 `rm -rf`、
`git clean` 或宽泛的 reset 猜测清理范围。

## 4. 恢复仓库自有资源

以下命令应从仓库根目录执行。它们覆盖已知资源，但不会删除未知文件：

```bash
cp -p 方案备份/snapshot/repository/ROOT.gitignore .gitignore
cp -p 方案备份/snapshot/repository/AGENTS.md AGENTS.md
cp -p 方案备份/snapshot/repository/opencode.json opencode.json

mkdir -p .opencode
cp -p 方案备份/snapshot/repository/.opencode/OPENCODE.gitignore \
  .opencode/.gitignore
cp -p 方案备份/snapshot/repository/.opencode/package.json \
  .opencode/package.json
cp -p 方案备份/snapshot/repository/.opencode/package-lock.json \
  .opencode/package-lock.json
cp -pR 方案备份/snapshot/repository/.opencode/agents .opencode/
cp -pR 方案备份/snapshot/repository/.opencode/commands .opencode/
cp -pR 方案备份/snapshot/repository/.opencode/skills .opencode/

cp -pR 方案备份/snapshot/repository/automation ./
mkdir -p scripts docs taskdescriptions
cp -pR 方案备份/snapshot/repository/scripts/automation scripts/
cp -pR 方案备份/snapshot/repository/docs/plans docs/
cp -p 方案备份/snapshot/repository/taskdescriptions/*.html \
  taskdescriptions/
```

如果插件化改造在这些目录中新增了文件，以上复制不会删除它们。请根据第 3
步的改造差异清单确认每个新增文件是否需要移走；不确定时先移动到临时目录，
不要直接删除。

## 5. 恢复依赖

精确旧配置使用 OpenCode `1.15.13` 和
`@opencode-ai/plugin@1.15.13`。恢复 package/lock 后，可让 OpenCode重新解析
项目配置，或在网络可用时根据 lock 重装 `.opencode` 依赖。

`opencode.json` 会重新声明：

```text
opencode-scheduler@1.3.0
superpowers@git+https://github.com/obra/superpowers.git#v6.2.0
```

若网络不可用，可使用 `external-dependencies/` 中的精确包副本进行人工核对。
OpenCode 缓存目录属于版本实现细节，不建议未经检查直接整目录覆盖。

## 6. 默认不要恢复运行审计

`runtime-audit/automation-runtime/` 与原仓库、分支、HEAD、绝对工作区路径和
sealed diff 绑定。它是审计副本，不是跨工程模板。

只有原 `.git/automation-runtime/` 被意外损坏、当前仍是同一 Git 仓库，并且
已确认三个任务均为 `COMPLETED` 时，才考虑将对应文件恢复到 Git common dir。
执行前应再次备份现有 runtime；不要把该目录复制到另一 Android 工程。

## 7. 恢复后验证

依次执行：

```bash
opencode debug config
opencode debug agent scheduled-planner
opencode debug agent scheduled-coder
opencode debug agent scheduled-reviewer
opencode debug skill
./scripts/automation/preflight.sh --source
./scripts/automation/tests/run-tests.sh
./scripts/automation/shadow-run.sh
```

然后检查：

- 三个本地 `scheduled-quality-*` Skill 均可发现；
- Superpowers 要求的五个 Skill 均可发现；
- 三个 Agent 权限与备份一致；
- Shell 测试为 `1..38` 且全部通过；
- shadow run 报告 `mutationPerformed: false`；
- 没有新增 launchd 任务；
- 没有执行 push；
- `git status` 中只包含明确保留的恢复或后续修改。

如果脚本可执行位在跨文件系统复制时丢失，可对照快照权限后只恢复
`scripts/automation/**/*.sh` 的可执行位；本次本机快照已原样保留权限。
